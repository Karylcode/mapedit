# 地圖以看得懂的文字檔為準

地圖存成專案資料夾裡一組看得懂的文字檔，這些檔案就是地圖本身。Agent 像改程式碼一樣直接改它們；編輯器像編譯器一樣讀檔，算出精確位置、檢查規則，把違規回報給 Agent 並標在網頁上；人在網頁上的修改也由編輯器寫回這些檔案。這讓 Agent 用它最擅長的讀寫文字，一次看到整張地圖，也能用 git 追蹤和復原。我們沒有採用「只能透過指令修改」：那樣每一步都會立刻檢查，但蓋大東西要呼叫很多次，Agent 也看不到全貌，而這正是現有 Unity／Blender MCP 最常被抱怨的地方。

## Consequences

- 檔案可能暫時有違規，所以「嚴格」的保證落在匯出：有違規的地圖不能匯出。
- 地圖拆成多個檔案（每個結構一個檔），避免一次塞爆 Agent 的上下文。
- 地形是例外：1 公里見方就有 100 萬個地塊，寫成文字太大，所以存成圖片（高度一張、地表一張），Agent 透過指令修改。
- 大量重複的東西（例如一整片森林）用散佈區描述，由程式擺出每一個，檔案才不會爆量。
- 人和 Agent 同時改到同一個東西時，以後改的為準並跳出提示；所有修改都能在編輯器裡復原，git 也留有完整紀錄。
